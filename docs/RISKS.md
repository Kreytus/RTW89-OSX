# Risk list (Phase 0)

Severity: **H** = can block a goal outright, **M** = big schedule or
performance cost, **L** = nuisance. "Gate" is the phase where the risk has to
be retired or accepted. Status of everything: **open**, nothing has been
tested on hardware.

| # | Risk | Sev | Evidence / exact blocker | Mitigation | Gate |
|---|---|---|---|---|---|
| R1 | **IO80211 on Sequoia/Tahoe has no maintained precedent** | H | itlwm last commit 2024-06-09; its V2 (Skywalk) glue targets Sonoma and depends on OCLP root patching of IO80211/IOSkywalkFamily. Private vtable layouts can change in any point release | Build the Skywalk glue against Sonoma first, then diff the vtables on 15 and 26 with class dumps of the kernel collection. Check every slot against a per-version table at `start()` and refuse to attach on mismatch | P1→P2 |
| R2 | **License conflict with mac80211** (decided: L1 clean-room, GPL-3.0 kept) | M | Repo is GPL-3.0; `net/mac80211`, `net/wireless`, `include/net/mac80211.h`, `cfg80211.h` are GPL-2.0-only | Clean-room rule: shim files are written without mac80211 sources open; review every shim header for copied text before merge | ongoing |
| R3 | **WPA3-SAE path unknown** | H | mac80211 has no SAE (wpa_supplicant does it on Linux). AirportItlwm downgrades SAE to WPA2 for mixed-mode networks only (`AirportItlwm.cpp:169`). We don't know where macOS runs SAE for non-Broadcom drivers | Disassemble IO80211Family/airportd on the target to see if SAE auth frames are passed through an Apple80211 request. Otherwise write an in-kext SAE (hash-to-element, ECC P-256 through corecrypto, which may not be accessible). WPA2 works first either way | P2 |
| R4 | **6 GHz reporting unknown** (now on the critical path: the test chip is 8852CE, 6E) | H | The reverse-engineered `apple80211_var.h`/`_ioctl.h` have no 6 GHz band or channel flags | Reverse the channel structs from Sonoma's IO80211 + WiFiAgent. 2.4/5 GHz ship first | P2 |
| R5 | **Size of "mac80211_lite"** | H | rtw89 depends on mac80211 for MLME, RX reorder, A-MSDU, PN check, TXQs, ADDBA (ARCHITECTURE §4.3). The equivalent Linux code is about 35 k lines (`rx/tx/mlme/agg-*/sta_info/key/scan/...`). The "thin shim" goal only covers the API layer | Implement STA-only, HE single-link, no mesh/TDLS/AP/MLO. Test it against packet captures from Linux | P2 |
| R6 | **Zero-copy RX with 11.5 KiB single-segment RX buffers** | M | `RTW89_PCI_RX_BUF_SIZE = 11454+40+4`, one RXBD = one address. mbuf clusters are 2/4 KiB, physical contiguity of 16 KiB jumbo clusters isn't guaranteed, and `mbuf_attachcluster` is not public KPI | Measure: (a) contiguous IOBMD buffers attached as external mbufs, (b) 3895-byte max MPDU with 4 KiB clusters, (c) copy fallback | P2 |
| R7 | **Realtek BT under Apple's bluetoothd** | H | No public report of a Realtek controller working on macOS 12+. BlueToolFixup's patches target Broadcom/Intel checks (vendor 0x0A5C etc.) | Test the HCI command log right after attach (PacketLogger). Expect gaps in LE features or vendor commands. Any extra bluetoothd patch would have to go upstream to BlueToolFixup with version checks | P3 |
| R8 | **HFP / SCO over USB isochronous** | M | The macOS 12+ BT transport is in user space. Isoch alt-setting selection for third-party controllers is known to be fragile | Test with mSBC and CVSD and document. Accept "partial" if needed | P3 |
| R9 | **No checksum offload or TSO** | M | rtw89 upstream has no checksum offload at all (no `CSUM` anywhere in the driver) | Look for an RX checksum bit in the vendor driver. Otherwise CPU checksums. Both are a cost against the ≥90% target that we measure, not assume | P2 |
| R10 | **Throughput parity without fq_codel/GRO-like batching** | M | The Linux ~800 Mbps figure relies on mac80211 TXQ + A-MSDU + GRO. The legacy IO80211 output path is one packet per call | Skywalk batched TX/RX on Sonoma+. Our own TXQs per TID. Measure ring sizes per PERF.md | P2 |
| R11 | **AWDL infeasibility** | H (for P5 only) | AWDL sync/election runs in Broadcom firmware. Realtek firmware has none. OWL needs active monitor mode + injection and is unmaintained. AirportItlwm's AWDL code is 58 lines of stubs | Phase 5 is research-gated: measure channel-switch latency and injection timing, then decide | P5 |
| R12 | **OCLP / SIP requirements** | M | Root patching requires lowered SIP and breaks OTA delta updates **[verify]** | Document clearly. Keep a non-root-patched path in mind if IO80211 allows it | P1 |
| R13 | **Firmware version drift** | L | rtw89 parses firmware format versions (`FW_FORMAT_MAX` 0..4 per chip). A newer `.bin` can need newer driver code | Pin linux-firmware commit next to the rtw89 commit and bundle that exact pair | P1 |
| R14 | **ACPI `_DSM` / BIOS regulatory data** | L | rtw89 calls `acpi_evaluate_dsm` for SAR/regd/6 GHz enablement. OpenCore ACPI differs from the OEM's | Use IOACPIPlatformDevice `evaluateObject`. Fall back to world regdomain | P1 |
| R15 | **ASPM/L1SS instability** | M | Linux exposes `disable_clkreq/aspm_l1/aspm_l1ss` because some platforms hang | Same three knobs as properties, defaulting to Linux defaults | P1 |
| R16 | **Upstream rebase churn** | M | rtw89 changes weekly (MLO and 8922D work) | Keep `#ifdef __APPLE__` hunks small and recorded. Rebase monthly | ongoing |
| R17 | **Firmware redistribution terms** | L | linux-firmware `WHENCE` must be checked for rtw89 and rtl_bt; it could not be fetched from the research environment | Read `WHENCE` at the pinned commit and ship the named licence file in Resources | P1 |
| R18 | **Research done on mainline, not wireless-next** | L | git.kernel.org was blocked (proxy 403) from the research environment | Re-run the inventory script on wireless-next before Phase 1 | P1 |
| R19 | **Only one boot medium** | H | The owner's only USB stick holds the OpenCore EFI. A boot-time panic from an injected kext would leave the machine unbootable | Runtime `kmutil load` only, never OpenCore injection during development. Make a second EFI copy on the internal ESP before touching config.plist (TESTING.md) | P1 |
| R20 | **No Linux baseline yet** | M | PERF.md compares against Linux rtw89 on the same card. That needs a Linux boot, and the only USB is taken | Install Linux on spare internal disk space and chain-load it from the OpenCore picker, or use a second stick. Until then, PERF.md uses published Linux numbers, labelled as such | P2 |
| R21 | **AMD platform** | M | AMD Ryzen hackintosh (patched kernel, AMD-Vi off). PCIe ASPM/L1SS, MSI and DMA are untested with this driver class on AMD | Phase 1a probe first, then MSI + DMA in Phase 1b with the ASPM knobs off by default | P1 |
| R22 | **Tahoe is the only test target** | H | 26.7 is the only macOS available for testing, and R1 says it has no IO80211 precedent | Do the IO80211 vtable/class-dump work on 26.7 first. 14/15 stay "untested" | P2 |
